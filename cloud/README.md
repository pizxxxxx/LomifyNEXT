# Аккаунт Lomify

Обычному пользователю достаточно открыть Настройки, Подключения, Аккаунт Lomify.
При первом запуске тот же вход предлагается в приветствии. Кнопка Жить в лесу
сохраняет локальный режим; войти можно позже. Пустой аккаунт автоматически получает
копию данных с этого компьютера. Если копия уже существует, сначала нужен выбор.
После выбора работает автосохранение изменившихся данных раз в пять минут.

## Бесплатный проект

Используются Firebase Authentication и Cloud Firestore Standard, тариф Spark.
Cloud Storage, Cloud Functions и платный сервер не нужны. Бесплатные квоты общие
для всего проекта: при исчерпании сохранение может стать недоступно до сброса
лимита. Тогда остаётся файл .lomi. Условия и квоты: https://firebase.google.com/pricing.

1. Открой https://console.firebase.google.com/ и создай проект. Оставь тариф Spark.
2. Authentication, Sign-in method: включи Email/Password и Google. Для Google
   введи название LomifyNEXT и выбери Support email for project.
3. Firestore Database, Create database: Standard edition, ID `(default)`, ближайший
   регион, Production mode. Scheduled backups не включай.
4. В Firestore Database открой Rules, вставь содержимое `cloud/firestore.rules`
   и нажми Publish. Оно допускает доступ только владельцу UID и ограничивает
   размер и структуру записей. Обычные owner-only правила также совместимы.
5. В Project settings зарегистрируй Web app без Firebase Hosting. В открытом
   firebaseConfig скопируй apiKey и projectId. Их можно включать в приложение:
   защиту обеспечивает вход и правила базы, а не сокрытие Web API key.

Публичная конфигурация текущего проекта находится в `src/lib/cloudConfig.ts`.
Другую сборку можно направить в свой проект через `VITE_FIREBASE_API_KEY` и
`VITE_FIREBASE_PROJECT_ID` в локальном `.env`. Аналитика не подключена.

## Google в настольной сборке

1. Открой Google Cloud, выбери тот же проект, затем Google Auth Platform, Clients,
   Create client. Тип Desktop app, название LomifyNEXT Desktop. Галочку
   Use this client for an AI-powered agent оставь выключенной.
2. Скопируй публичный Client ID в `VITE_GOOGLE_DESKTOP_CLIENT_ID` для своей сборки.
3. Скачай JSON именно этого Desktop app и сохрани локально как
   `src-tauri/google-desktop.local.json`. Этот файл исключён из Git. Web application,
   Admin SDK и serviceAccount файлы здесь не подходят.
4. Пересобери приложение. `build.rs` читает только installed-конфигурацию и включает
   регистрационные параметры Desktop app в нативную часть. Без файла Google-вход
   недоступен, но почта и локальный режим работают.
5. Если Google ограничивает приложение тестовыми пользователями, в Google Auth
   Platform, Audience добавь свою почту в Test users. Перед общим выпуском проверь
   публикацию приложения и требования Google к названию и странице поддержки.

Google требует client_secret даже для Desktop app с PKCE. Он является параметром
регистрации распространяемого клиента и не может быть серверным секретом в бинарнике.
Защита сеанса использует случайный state, PKCE S256 и короткоживущий callback только
на 127.0.0.1 со случайным портом. Пароль вводится в обычном браузере Google.
Lomify получает подтверждение Google, обменивает его на Firebase-сеанс и хранит
refresh token в системном keyring. Пароли и токены не пишутся в localStorage.

## Данные и восстановление

- .lomi: JSON формата lomify-backup, версия 1, максимум 64 МиБ. Аудиофайлы и
  подключения сервисов не включаются. Локальные пути остаются для того же ПК.
- Облако: максимум 4 МиБ на копию. Текст делится на ограниченные части. Все части
  и манифест записываются одним атомарным commit; условие updateTime защищает от
  перезаписи более новой копии. Загрузка проверяет ревизии, размер и SHA-256.
- Облачная копия сохраняет часы, историю, любимые и скрытые песни, плейлисты,
  достижения, оформление и эквалайзер. Аудио, служебные токены, привязки сервисов
  и пути к папкам не загружаются. Локальные ID с путями заменяются непрямыми ID.
- Загрузка копии требует просмотра, явного выбора и сохранения нынешних данных
  отдельным .lomi. Локальные аудиозаписи на данном ПК сохраняются при облачной
  загрузке. При восстановлении синхронизация музыкальных сервисов приостанавливается.
- Автосохранение никогда не загружает в новый пустой ПК старую облачную копию без
  выбора пользователя и не заменяет существующую облачную копию при самом входе.

## Проверки

`node --test scripts/lomi-cloud-test.mjs`

`node --experimental-vm-modules --test scripts/lomi-restore-test.mjs`

`node scripts/cloud-live-smoke.mjs --live` создаёт два временных тестовых аккаунта,
проверяет запись, чтение и изоляцию владельца, затем удаляет только их записи
и сами тестовые аккаунты. Реальные пользовательские данные не читаются.
